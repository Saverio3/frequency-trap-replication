# Controlled real-Robyn experiment: is the daily-versus-weekly difference due to temporal aggregation? (design fixed BEFORE any result, 24 Oct 2026)

Reviewer 1's concern: a difference between "Robyn on daily data" and "Robyn on weekly data" may come from data volume, model selection or optimisation, not from temporal aggregation. The earlier real-Robyn test (DESIGN_ROBYN_REAL.md, 12 single-channel markets) cannot separate these, because its daily arm also had 7x the observations and a weekday term. This experiment keeps the market, the model, the KPI and the evaluation identical and changes only where the media transformation is applied.

## Software
Robyn 3.12.1, Meta's R code unmodified EXCEPT for one switch inside `run_transformations()` (transformation.R) that is inactive unless the environment variable ROBYN_DAILY_SPEND_FILE is set. With the variable unset the code path is Meta's. The helper package lares is a stand-in (clustering off), as before. Patched package: robyn_pkg_B (installed in rlibB). Nevergrad TwoPointsDE through reticulate, as before.

## Markets (fresh seeds, prefix "RXM"; exporter export_robyn_mc.py)
16 simulated markets, 156 weeks of underlying daily data (1,092 days), 3 channels per market (ch1, ch2, ch3). The generator is the multichannel generator of DESIGN_MULTI.md (spend patterns bursty / smooth / real / flighting / pulsing / sporadic, decay 0.15 / 0.50 / 0.85, depth mild / med / deep, Hill shape 1.0 / 2.2, shares Dirichlet(2), signal R2 0.85), with one change needed for a daily KPI: the daily KPI is baseline/7 + sum of channel daily responses (scaled) + daily noise, so that the weekly KPI is exactly the sum of the seven daily values (as in the single-channel export). No price control and no weekday effect in the truth (a weekday effect in the response is a separate, already reported limitation).
Market types (market id mod 4, so any prefix of the run order is balanced): ids 0, 1 mod 4 = INDEPENDENT (all channels DAILY truth, no spend correlation, M1 type); id 2 mod 4 = CORRELATED (all DAILY truth, spend tilted by a shared factor, kappa 1, M2 type); id 3 mod 4 = MIXED (one channel has a WEEKLY true process, the others DAILY, M3 type). The mixed markets are a falsification check: if the daily-transform arm also wins there, the advantage is not coming from the transformation.
Truth: the true total contribution of each channel over the 156 weeks (what Robyn's decomposition estimates).

## Arms (the same market in all arms)
A. Standard weekly Robyn: weekly spend, weekly KPI, Robyn's own adstock and saturation on weekly media, Prophet trend and season.
B. Daily transformation, weekly outcome (PRIMARY comparison with A): the same weekly KPI and the same weekly Prophet decomposition as A; adstock and Hill saturation are applied to the DAILY spend (Robyn's own adstock_geometric and saturation_hill functions on the daily adstocked series of the rolling window) and the transformed daily media is summed to the 156 weekly model rows. Regression, ridge, validation split, objectives, search, Pareto step and scoring are Meta's code and identical to A.
C. Standard daily Robyn (SECONDARY, practitioner workflow): daily KPI and daily spend, Prophet trend, season and weekday. NOT a clean test of frequency (7x observations, weekday term, different meaning of the validation split); reported as the practitioner's daily-versus-weekly choice.
Held constant across arms: simulated market, hyperparameter bounds (alphas 0.5-3, gammas 0.05-1, thetas 0.01-0.95 for every channel, train_size 0.5-0.9; the same numbers at both frequencies, whose meaning differs: stated), search algorithm TwoPointsDE, iterations and trials, seed argument, ridge by glmnet, validation scheme (time-series split), Pareto step, the selection rule, the evaluation metric. Not held constant in C: number of observations, weekday term.
Known interpretive differences, stated in advance: (1) Robyn's saturation inflexion is gamma times the maximum of the adstocked series within the window; at daily frequency that maximum is a daily maximum, so the same gamma means a different absolute half-saturation than at weekly frequency; (2) theta is a per-day decay in B and C and a per-week decay in A.

## Selection rule (declared)
Robyn's Pareto-1 models. PRIMARY rule: the Pareto-1 model with the lowest Robyn error_score (the combined score of validation NRMSE and DECOMP.RSSD that Robyn uses to rank models). SECONDARY rule: lowest validation NRMSE among the Pareto-1 models. Clustering is not available (lares) and is not used; both rules are reported for every run. No other selection is made after seeing results.

## Metrics
Total media contribution bias % = 100 (sum of 3 channel estimates - sum of truth) / sum of truth; per-channel bias %; mean |bias| by arm and market type; paired differences A minus B (primary) and A minus C (secondary) with the 2-SE rule, sign counts (markets in which B is better), and the same split by market type (independent, correlated, mixed). Also reported: the share of runs in which Robyn's own convergence message ("NRMSE/RSSD not converged") appears, and the number of Pareto-1 models.

## Run size (tiers; the tier is fixed per run, never per market)
FULL = Robyn's recommended setting, 2,000 iterations x 5 trials per model. PILOT = lower setting used only to test the pipeline and to time it. The tier used for the main comparison is declared in a dated note below, before the main run, after timing and equivalence tests (no results looked at). If compute does not allow FULL for all 16 markets, the markets are run in id order (balanced by type) and the number completed is reported; an arm comparison is only made on markets where all three arms finished.
Noise check: markets 0, 2 and 3 (one of each type) are re-run twice more for arms A and B at the main tier, to measure run-to-run variation (same-seed repeats are not reproducible, see DESIGN_ROBYN_REAL.md, note 2).

## Validation before any experiment runs (pass/fail declared now)
T1. With ROBYN_DAILY_BLOCK=1 and the daily file set equal to the WEEKLY spend, the patched transformation must reproduce standard Robyn's output (saturated media, immediate and carryover parts, inflexions) to within 1e-10 for 20 random hyperparameter draws.
T2. With block 7, the patched weekly media must equal an independent Python implementation (daily geometric adstock, Hill with inflexion gamma x max of the window's daily adstock, 7-day sums) to within 1e-8 for 20 random draws.
T3. A short end-to-end run of arms A, B, C on one market must complete and return contributions.
If T1 or T2 fails the experiment does not start.

## Not covered (stated in advance)
Weekday effects in the response; holidays/paydays; Robyn's clustering of Pareto models; calibration with experiments; more than 3 channels; paid-media variables other than spend; non-geometric adstock; Robyn versions other than 3.12.1; and any claim about the Robyn package in general beyond these simulated markets.

## Notes added before the main run (24 Oct 2026; equivalence tests and one 300-iteration smoke run done, no experiment results looked at)
1. Equivalence tests PASSED: T1 (patched block 1 on weekly data versus standard Robyn): maximum absolute difference 0.0 over 20 random draws (saturated media, immediate, carryover, inflexions); T2 (patched block 7 versus an independent Python daily transform with Robyn's rule inflexion = gamma x max of the window's daily adstock): maximum absolute difference 1.1e-12. The daily and weekly transformed media differ materially (mean absolute difference 0.27 against a mean level of 0.21), so the test is not vacuous. T3 (end-to-end smoke test, market 0, 300 iterations x 1 trial, arms A, B, C): completed. These 300-iteration estimates are NOT results (Robyn's own convergence message reported "not converged" and the estimates are far from the truth); they are discarded.
2. Timing (2 cores): about 0.2 seconds per iteration, so FULL (2,000 iterations x 5 trials = 10,000 evaluations per model) is about 35 minutes per arm run, about 1.8 hours per market with 3 arms.
3. Tier for the main comparison: FULL (2,000 x 5). Arms A and B on all 16 markets; arm C (secondary) only on markets 0-7 to save compute. Run order by market id (balanced by type); whatever finishes is reported, and comparisons use only markets where the arms in the comparison finished. Output: results/RXM_full.csv (cloud run) and any laptop run files, merged by market and arm; if the same market and arm is run twice it counts as a repeat (noise), not as a second market.
4. Real compute available in the cloud workspace is 2 cores, so the full 16-market run is about 1 day there; a laptop with 8 cores should take roughly 7 to 10 hours.
